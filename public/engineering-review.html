BANDROOM / ENGINEERING REVIEW

工程验收记录

适用于 Bandroom 第二个发布版本。测试账号、录音夹具和模拟课包仅用于回归。

返回我的练习室

修复与验证

课程与并发
服务端按账号和版本校验提交。重复提交同一份数据只写一次，其他设备的冲突提交会提示重新读取。独立首稿、首次答案和既有录音均受保护。隔离数据库从 Day 11 运行到 Day 62，覆盖 1,181 次提交、2,451 项断言。
会话与设备
首次登录校验前显示读取状态；登录过期时保留当前表单。浏览器测试在保存口语草稿期间使会话过期，恢复同账号后逐字核对草稿，再从另一个页面读到已打卡状态。不同账号的草稿与云端记录分开。
录音与教练
用真实编码的 WebM/Opus、OGG/Opus、MP4/AAC、WAV/PCM 检验上传、范围读取、重组、解码与越权拒绝。教练可以读取本人已提交的音轨、追加评语并回读。半分制发音专项估分需要提交过的录音、评阅者的整段听取确认和具体听辨依据。单题记录为专项暂定结果。
备份与恢复
设置页可导出签名备份。归档包含学习记录、报告、已发布课包、教练评语和引用的录音。导入先验签、核对账号和文件摘要，再预览可补回的内容。恢复可重试，遇到较新或不同的记录会停止。已在隔离 D1 与 R2 环境完成备份、缺失数据恢复和逐字节比对。
窄屏布局
修复 320 像素布局中导航超出右侧的问题。以真实 Chromium 渲染检查首页、学习档案、错题手记、阶段评估、设置及口语打卡路径。验证范围是响应式网页与浏览器交互；各型号手机的麦克风授权和 Safari 系统行为取决于设备。
课包与目标
核对 Day 12–16 全部五份内置课包、20 道听读客观题的选项与答案索引，并实测五份听力资源可分段读取。Day 17–62 按学习表现编排。测试使用账号专属模拟课包走到最后一课，也检查没有已发布课包时阻止开课。首页、设置、阶段评估与教练使用同一组目标：听力 8.5、阅读 9、写作 8.5、口语 7.5，总分 8.5。

复现检查

在源码检出目录中使用 Node.js 24、项目依赖和 FFmpeg。Miniflare 测试启动临时本地 Worker，测试结束后清理数据。

npm run test:review
./node_modules/.bin/tsc --noEmit --incremental false
npm run build

回归代码位于 tests/。状态测试使用真实 SQLite 和应用路由，备份测试另行运行于本地 D1/R2。正式账号用于回读进度和已有录音。

恢复范围

备份保存在持有人选择的位置。设备本地录音需从存有原音的浏览器导出；恢复签名绑定原站点和账号。运维需保留原站点的签名密钥，轮换时应安排版本兼容。单份归档上限 512 MiB，每段录音上限 12 MiB。

课程打卡、工程测试和 IELTS 成绩分别记录。测试夹具产生的评分不进入个人学习档案。
