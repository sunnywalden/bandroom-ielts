# Bandroom 网站触发 Work 批改方案

本方案以源码 `bda9ce34ec4da029c6b0f7a814ad35d89a7f5ba5` 为基线。评审结论和验收条件已纳入本文。文字和录音自动批改分别启用，取决于隔离站点与真实云端 Work 会话的验收结果。

## 1. 当前能力与交付范围

Bandroom 已能按具体作答从 Work 读取与回写反馈。当前页面提示用户在 Work 发起批改，站点在页面可见时同步反馈。现有 MCP 端点只声明工具能力，Sites 的站点配置包含 D1、R2 和 MCP。这里已有批改回写链路，网站触发还需要事件订阅和后台投递。 [工具端点](../app/mcp/route.ts) · [现有反馈界面](../app/attempt-feedback.tsx) · [同步逻辑](../app/studio.tsx) · [站点配置](../.openai/hosting.json)

OpenAI 的 MCP Events 支持云端 Work 会话订阅事件。用户在所选会话授权一次，站点在答题提交后向该订阅的回调发送事件，由 Work 执行约定的批改任务。Bandroom 只使用已核验订阅提供的回调定位会话。实际能否发现站点事件、使用同一账号、自动写回，以及该会话是否允许按事件运行，均以真实会话测试为准。Work 的工作区控制和使用额度适用。 [MCP Events](https://developers.openai.com/plugins/build/mcp-events) · [Work 使用量和费用](https://learn.chatgpt.com/docs/enterprise/chatgpt-work-usage-and-cost)

| 练习 | 提交后立即显示 | 本题 Work 批改 |
| --- | --- | --- |
| 口语 Part 2、Part 3 | 录音或文字的实际保存状态，可播放时提供回听 | 按该次回答评内容。发音与流利度须通过录音验收并实际听到该段录音 |
| 口语自评 | 已保存的自评 | 针对自评给出一项可练习的改进 |
| 词汇回忆和造句 | 回忆题即时核对，展示造句及保存状态 | 逐句纠正造句、搭配和语法 |
| 听力 | 逐题核对选择及解释，显示实际播放条件 | 现有题型由答案键批改 |
| 阅读 | 逐题核对选择及解释 | 单独评价该题填写的证据说明，结合原文指出问题 |
| 写作首稿和修订稿 | 分别显示已保存的版本与字数 | 首稿与修订稿独立反馈，修订稿结合对应首稿及修改意图 |
| 本课复盘 | 通过「提交复盘」独立保存，可在当前环节查看建议 | 针对复盘给出下一步练习。打卡由用户单独操作 |

每题显示批改状态，保存成功后可继续练习。批改在后台处理，返回后落在原题的原提交版本，离开页面后可从学习档案回看。完成课程、启动下一天、课程成绩和历史反馈走各自现有的入口。正式验收使用隔离站点和虚构学习记录，保护真实 Day 12 的录音、成绩与进度。

## 2. 提交事务和作答身份

沿用现有状态接口的身份、来源、修订号、合法状态转换和录音归属校验。只在用户明确提交一个主观回答时附带批改提交参数。服务端由提交前后的合法状态推导唯一题目及作答，核对页面所见题目版本。若题目变更、没有合法的新答复或同时涉及多题，提示核对并保留草稿。草稿同步、客观题核对和导航采用现有保存路径。复盘使用当前环节内的显式提交，打卡仍由单独的用户操作触发。 [状态接口](../app/api/state/route.ts) · [状态转换](../app/api/state/transition.ts) · [逐题提交入口](../app/exercise.tsx)

每个明确提交使用一个客户端生成的 `submissionKey`。在收到结果前，冻结该次请求和键，按账号保存于现有本地恢复机制。服务端对标准化请求计算摘要，纳入基准修订号、题目版本和提交内容。以 `(owner, submissionKey)` 查收据，再决定是否比较当前修订号。相同键和摘要返回最初收据，即使后来已保存别的题。相同键的不同请求返回 `submission_key_conflict`。并发的不同提交若基准过旧，返回 `revision_conflict`，页面先读回、保留本地草稿，再让用户确认是否确实要新交一次。

在现有 D1 数据库增设 `review_jobs` 和 `review_subscriptions`，在 `teacher_feedback` 加可空且唯一的 `review_job_id`。任务行同时保存不可变的提交收据及作答快照，以及独立的可变批改和投递状态。成功提交时，`review_jobs.id` 由服务端生成，`v2:<id>` 作为此次作答标识。保留既有 `v1` 标识供历史显示。 [现有数据表](../db/schema.ts) · [既有作答标识](../app/feedback-model.ts)

| 数据 | 内容 |
| --- | --- |
| 收据 | 账号、提交键与摘要、已提交修订号、题号和 `attemptId`。读回收据独立于读取当前学习进度 |
| 快照 | 题目和批改标准版本、提交文本、相关材料或可验证的冻结引用、作答条件、服务端提交时间。阅读保留所选选项和证据句，写作修订稿关联对应首稿 |
| 录音引用 | R2 所有者、对象 ID、题号、口语阶段、类型及内容摘要。设备内录音明确标注为仅在该设备可用 |
| 任务与订阅 | 当前批改与投递状态、订阅纪元、通知代次、重试时间和次数、领取凭据摘要及过期时间 |

**同一事务提交。** 先按原流程完成录音上传和归属校验，沿用条件写入的录音 ID。将答题进度与批改快照放在同一个 `D1.batch()`。以修订号和唯一提交键有条件插入任务，再仅凭这次新生成的任务 ID 有条件更新进度，兼容初始空记录。事务内检查新任务存在时进度也已进入预期修订号和内容，违反条件则整批回滚。条件写入跳过时以权威收据读回区分重放与冲突。事务返回收据后，投递器才处理事件。 [录音上传](../app/api/audio/route.ts) · [D1 批处理](https://developers.cloudflare.com/d1/worker-api/d1-database/#batch)

录音对象先持久化，数据库引用随后提交。上传成功但数据库失败时，设备保留原录音和请求，重试复用上传 ID。已提交后断线或刷新时，按键读回收据并拉取最新进度，避免旧回执覆盖新进度。已提交的题由 `attemptId` 定位，重新作答使用新的版本和任务。学习档案按快照与反馈对应显示，各版本独立保留。

## 3. 订阅、投递和 Work 权限

1. **一次授权。** 在用户选中的云端 Work 会话连接批改入口并设置事件任务。批改 MCP 入口声明 `events`，实现 `events/list`、`events/subscribe` 和 `events/unsubscribe`。用实际验证的连接主体绑定 Bandroom 账号、站点环境和事件过滤条件。每个账号只保留一个启用的批改订阅。回调以签名挑战验证通过后才启用，持久保存到期时间和加密签名密钥。续订、取消和重新绑定均按认证主体和当前纪元有条件写入。撤销或替换时使旧投递和领取资格失效，旧任务由用户选择是否重试。
2. **保存后投递。** 后台投递器从 D1 限时领取到期的待发任务，发送 `bandroom.review.requested`，应用载荷仅含任务 ID 和通知代次。领取时记录发送次数，投递器故障后可在领取到期时接手。每次逻辑通知有固定事件 ID，网络重试沿用它并重新签名。仅当前投递领取、订阅纪元和通知代次可记录发送结果。已被 Work 领取或完成的任务保留其批改状态。验证与投递均校验公开 HTTPS 目标，在实际连接时固定已验证的地址并保留原域名做 TLS 校验，禁止重定向。回调地址只来自受信任的订阅流程。 [MCP Events 验证和投递](https://developers.openai.com/plugins/build/mcp-events#verify-the-callback)
3. **按事件领取。** 自动入口只开放 `claim_review_job`、`read_review_job` 和 `complete_review_job`。Work 根据事件逐项领取已授权的任务，领取时原子校验账号、订阅纪元、通知代次和状态，发放限时凭据。读取限于该任务的冻结快照及允许的录音。通过单独的受限入口或 Work 可验证的同等权限隔离，让自动会话只能访问本题所需数据和反馈写入。验收实际工具清单及拒绝结果，包括拒绝调用现有 `publish_lesson`、读取其他题或其他账号。普通会话沿用原有教学工具。 [现有工具权限面](../lib/coach.ts)
4. **确认后台能力。** 自动投递依赖 Sites 实际支持的后台调度及上述 HTTPS 传输。请求成功后的即时唤起可缩短等待，持久化后台恢复仍须独立通过验收。若当前环境无法提供合规传输或关页后重试，保留手动 Work 批改。独立托管的投递器仅在另行授权且通过同样验收时进入部署范围，模型调用继续使用 Work。

后台投递与页面轮询是两条独立链路。Work 按订阅事件触发，可批量接收多条通知。服务端以任务和领取凭据判断重复、迟到或无权限调用。Webhook 的 `2xx` 仅代表收件，页面从 Bandroom 的任务状态确认是否领取或完成。 [MCP Events 响应和订阅生命周期](https://developers.openai.com/plugins/build/mcp-events#handle-delivery-responses)

## 4. 状态、重试和反馈写回

| 作答保存 | 批改任务 | 页面和恢复动作 |
| --- | --- | --- |
| 等待提交确认 | 等待收据 | 显示「正在保存」。超时保留本地录音和草稿，用原键核对或重试 |
| 已保存 | `queued` | 显示「已保存，等待 Work 领取」。后台继续投递，关闭页面后可读回 |
| 已保存 | `running` | 显示「Work 已领取」。可继续下一题，领取过期后显示恢复操作 |
| 已保存 | `done` | 显示逐句批改，可在原题和档案查看原文、改写、理由和下一步练习 |
| 已保存 | `needs_action` | 告知可核实的原因，按情况重新连接、重试本次批改或生成本题的手动 Work 请求 |

- **投递重试。** 网络异常、限流及暂时服务故障按有限次数退避。试运行参数为每个通知最多三次发送，两次重试分别间隔 30 秒和 2 分钟。尚未领取的任务在投递耗尽时显示 `WORK_DELIVERY_FAILED`，缺少有效订阅时显示 `WORK_CONNECTION_REQUIRED`。回调 `410` 停用对应订阅，`413` 转配置错误。收到 `2xx` 后 5 分钟仍未领取时显示 `WORK_NOT_CLAIMED`，提示「Work 暂未领取」。Work 领取有效期试设 10 分钟，期满且未写回时显示 `WORK_REVIEW_TIMEOUT`，可由用户重试。重试增加通知代次并撤销旧领取资格。上述时限在隔离验收后按实测调整。
- **权限和手动恢复。** 登录失效时保留账号隔离的本地数据，同一账号重新认证后先核对收据。订阅失效时冻结相应自动任务，明确显示连接状态，重新连接后由用户选择要重试的任务。手动接手时，站点先撤销该任务的自动投递和领取资格，再生成只能用于该任务的限时请求。现有手动工具接入同一份快照和写入校验。对已纳入新流程的作答使用对应 `v2` 路径，避免手动入口同时按 `v1` 写入第二份结果。
- **反馈写回。** 任务仍处于当前有效领取时，在一个 D1 事务插入反馈并把任务标为 `done`。对自动领取同时校验当前订阅纪元和有效期，对手动领取校验站点签发的限时权限。服务端从冻结快照取账号、天数、阶段及 `attemptId`，验证结果结构和引用。`review_job_id` 唯一约束保证每次提交一份正式结果。相同有效凭据重放返回原收据，内容不同也只能读取原收据。过期或已撤销的领取不能写入。批改事务只写任务和反馈，页面始终按原提交版本查找。
- **内容和证据。** Work 将作答、阅读材料和转写当作待分析的数据。输出使用受限结构，英语原文与改写相邻，用中文解释原因，给一项下次可做的练习。文本引用由服务端与快照核对，网页按文本显示。日志只记任务 ID、状态、耗时和原因码。录音、答案正文、签名密钥和领取凭据只进入各自授权的数据路径。
- **页面读回。** 对可见页面中的待批改题，试运行每 3 秒刷新状态，恢复焦点立即读回。完成后停止该题轮询，旧请求的结果和错误都按账号与作答版本核对。网络失败时保留已显示结果及草稿，提供刷新。前台展示验收目标为反馈落库后 5 秒内可见，Work 实际批改耗时单独记录。

## 5. 录音、备份与回退

文字批改先验收。录音用独立开关，根据云端 Work 真实可消费的格式和大小开放。只有能在实际批改运行中取得并听到对应录音，才提供该段的发音及流利度反馈。仅有文字或转写时按文字给反馈并明示范围。仅有设备录音且无文本时，显示可核对的录音状态并提供重新上传或手动回听入口。技术验证区分文件可读、可解码与 Work 实际接收声音。 [现有音频工具](../lib/coach.ts)

数据库迁移只增补。备份扩展签名清单，保存不可变作答快照、提交收据、关联反馈及快照引用的录音，同时支持读取现有 v1 备份。沿用并测试现有容量上限和恢复时的冲突校验。恢复只导入历史记录，未批改的作答进入可手动处理状态，自动批改需重新授权。活跃订阅、签名密钥和领取凭据排除在备份之外。 [备份格式](../lib/backup-format.ts) · [现有恢复](../lib/backup.ts)

回退先关闭自动入口和投递，再使旧领取资格失效。保留增量数据表、录音与评语，由兼容 `v1`、`v2` 的页面读出，用户仍可在 Work 手动处理。发布前先在隔离站点验证开关回退、旧版本读取和备份恢复。旧部署包只有通过新数据可读性验收才纳入回退路径。

## 6. 上线验收

| 门槛 | 验收证据 | 未通过时 |
| --- | --- | --- |
| G1 云端 Work 事件与权限 | 在隔离私人站点上，用真实云端 Work 会话发现和订阅事件。挑战成功，实际事件由所选会话领取并在约定授权范围内回写。每题无需再确认。验证错误主体、跨题访问和课程发布均被拒绝 | 保留手动触发，自动入口关闭 |
| G2 离线投递与安全 | 真实托管环境记录 `保存 → 发送 → 收件 → 领取 → 写回 → 页面可见`。关页、首次失败、投递进程重启后仍能恢复。验证重复与乱序、过期签名、私有地址、DNS 改绑及重定向拦截 | 保留手动触发，自动入口关闭 |
| G3 文字及状态回归 | 浏览器与学习接口覆盖每个主观环节和客观题即时核对，注入保存失败、Work 写回失败、延迟、双击、刷新、双页并发、过期登录、丢失回执、手动接手及迟到反馈。自动批改前后比对测试账号已有的 Day 12 Part 2 录音、旧成绩、历史反馈、当前进度及 Day 13 的开启状态，另测用户手动打卡 | 继续隔离测试 |
| G4 录音证据 | 使用可听内容明确不同的合成样本，核对 Work 读取的是目标题及目标版本，并能在工具运行中辨别样本实际声音。覆盖大文件、设备内录音、只有转写、权限失效及音频格式不受支持 | 录音自动批改关闭，可用文字路径继续 |
| G5 私人启用与回退 | 在隔离私人站点验证启用开关、备份读取、兼容版本及回退恢复。比对回退前后的历史记录、录音和反馈，并验证过期事件失效 | 保持手动 Work 路径 |

G1、G2、G3、G5 全部通过后才启用文字自动批改，录音再要求 G4。真实验收采用独立 D1 和 R2 及虚构回答。记录 Work 授权范围、实际运行额度表现和端到端用时。正式启用时记录站点版本、代码 SHA 和验收证据。批改沿用现有 Work 账号和该账号可用的运行额度。
